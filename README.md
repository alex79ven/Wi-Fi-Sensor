# Wi-Fi-Sensor

Универсальный узел умного дома на базе **ESP8266 ESP-12F**. Плата объединяет датчики температуры, влажности, давления, освещённости и движения, а также опциональные измерители CO₂ и электроэнергии. Устройство умеет управлять двумя каналами нагрузки, работать по Wi-Fi, отдавать данные через MQTT и интегрироваться с OpenHAB.

Этот репозиторий является форком проекта [kmaximv/Wi-Fi-Sensor](https://github.com/kmaximv/Wi-Fi-Sensor). Прошивка и печатная плата относятся к исходному проекту; README описывает функциональность, архитектуру и ограничения форка.

## Возможности

### Датчики и измерения

- температура и влажность;
- атмосферное давление;
- освещённость в lux;
- обнаружение движения;
- до двух внешних температурных датчиков DS18x20;
- содержание CO₂;
- напряжение, ток, мощность и потреблённая энергия;
- диагностические данные: uptime, версия прошивки, IP, MAC и свободная память.

### Управление нагрузкой

- два независимых канала управления;
- режимы `ON`, `OFF` и `AUTO`;
- автоматическое включение по движению и уровню освещённости;
- настраиваемая задержка выключения;
- плавное изменение яркости через ШИМ;
- управление низковольтными LED-лентами;
- отдельный вариант платы с твердотельным реле для нагрузки 220 В.

### Сеть и автоматизация

- Wi-Fi в режимах STA, AP и AP_STA;
- первоначальная настройка Wi-Fi через web-интерфейс;
- MQTT publish/subscribe;
- интеграционные файлы для OpenHAB;
- NTP для синхронизации времени;
- настройка статического IP;
- web-страницы состояния и конфигурации;
- журнал событий и диагностические сообщения.

## Архитектура

```text
Датчики и кнопки
       │
       ├── DHT22 / BME280 / SHT21
       ├── BH1750
       ├── HC-SR501
       ├── DS18B20 / DS18S20
       ├── MH-Z19
       └── PZEM-004T
       │
       ▼
 ESP8266 ESP-12F
       │
       ├── Wi-Fi
       ├── Web UI
       ├── MQTT
       └── OpenHAB
       │
       ├── канал 1: MOSFET / низковольтная нагрузка
       └── канал 2: MOSFET или SSR 220 В
```

ESP8266 считывает датчики, принимает команды управления, управляет выходами и публикует состояние в MQTT. OpenHAB или другой MQTT-клиент может отображать значения и отправлять команды.

## Поддерживаемые компоненты

| Компонент | Назначение |
|---|---|
| ESP8266 ESP-12F | Wi-Fi-микроконтроллер |
| DHT22 | температура и влажность |
| BME280 | температура, влажность и давление |
| SHT21 / HTU21D | температура и влажность |
| BH1750 | освещённость |
| HC-SR501 | датчик движения |
| DS18B20 / DS18S20 | внешние температурные датчики |
| MH-Z19 | измерение CO₂ |
| PZEM-004T | измерение параметров электросети |
| MOSFET | управление низковольтной нагрузкой |
| SSR | управление нагрузкой 220 В в отдельном варианте платы |

Поддержка датчика в прошивке не означает, что он обязательно установлен. Перед включением проверь `user_config.h`, `json_config.h` и фактическую схему подключения.

## Режимы работы нагрузки

### `ON`

Нагрузка включается независимо от датчиков освещённости и движения.

### `OFF`

Нагрузка выключается.

### `AUTO`

Автоматический режим использует датчик движения и BH1750:

1. При обнаружении движения нагрузка включается.
2. Если освещённость ниже заданного порога, освещение включается.
3. После исчезновения движения нагрузка выключается через настраиваемую задержку.
4. При необходимости включение и выключение выполняются с плавным изменением яркости.

У каждого канала могут быть собственные порог освещённости и задержка выключения.

## MQTT

MQTT используется для обмена данными и командами. Имена топиков формируются из настроек:

- базовый топик публикации;
- базовый топик команд;
- имя устройства `mqtt_name`.

В прошивке предусмотрены публикации:

- температуры;
- влажности;
- давления;
- освещённости;
- состояния движения;
- состояния каналов нагрузки;
- CO₂;
- параметров PZEM;
- uptime, IP, MAC, версии и свободной памяти.

Подписки позволяют управлять:

- каналами нагрузки;
- задержкой выключения;
- сбросом счётчика PZEM;
- обновлением сессии MQTT;
- дополнительным управлением котлом, если включён соответствующий compile-time модуль.

В `OpenHab` находятся готовые конфигурации items, rules, persistence и sitemaps. Их можно адаптировать под свой MQTT-брокер и схему подключения.

## Web-интерфейс

Прошивка поднимает встроенный HTTP web-сервер и Wi-Fi Manager. Через него выполняются первоначальная настройка и просмотр состояния устройства.

Веб-интерфейс не следует публиковать в Интернет без дополнительной аутентификации и шифрования. Используйте его только в доверенной локальной сети.

## Конфигурация

Основные параметры находятся в:

```text
esp_sensor/user_config.h
esp_sensor/json_config.h
```

Compile-time параметры определяют, какие модули и датчики включены при сборке. После загрузки прошивки настройки хранятся в конфигурационном файле `conf.json` на SPIFFS.

Типичные параметры:

- Wi-Fi: STA/AP/AP_STA, SSID, пароль, режим шифрования;
- статический IP и шлюз;
- MQTT-сервер, порт, пользователь и пароль;
- базовые топики MQTT;
- пины датчиков и реле;
- порог освещённости;
- задержку выключения;
- период опроса и публикации;
- параметры NTP;
- уровень журналирования.

### Важно о пинах

Примеры пинов в конфигурации являются параметрами проекта, а не универсальной схемой wiring. Проверь схему перед подключением. В исходных настройках встречаются потенциальные конфликты между некоторыми датчиками, кнопкой сброса и выходами реле.

## Сборка и прошивка

Проект построен в стиле Arduino для ESP8266. Установите:

1. Arduino IDE;
2. поддержку плат ESP8266;
3. библиотеки, перечисленные в исходниках и `esp_sensor/libraries`.

Откройте:

```text
esp_sensor/esp_sensor.ino
```

Выбери подходящую плату ESP8266 и проверь параметры загрузки. Перед первой прошивкой обязательно проверь:

- тип ESP8266;
- пины датчиков;
- пины реле;
- скорость UART;
- настройки PZEM и MH-Z19;
- параметры Wi-Fi и MQTT.

После первой загрузки устройство может поднять точку доступа или web-интерфейс для настройки. Не используй параметры из репозитория как production-пароли.

## Ограничения

- Это старая Arduino-прошивка; при современной сборке может потребоваться обновление библиотек и ядра ESP8266.
- Физически доступные датчики зависят от варианта печатной платы и подключения.
- PZEM-004T и MH-Z19 используют UART; их одновременная работа требует проверки и может конфликтовать.
- Конфигурация по умолчанию содержит параметры, которые обязательно нужно заменить.
- MQTT-аутентификация включается отдельно и по умолчанию может быть отключена.
- Web-сервер рассчитан на локальную сеть, а не для прямого публичного доступа.
- Устройство не является промышленным контроллером безопасности.

## Безопасность

### Электрическая нагрузка

Вариант с SSR для 220 В не имеет гальванической изоляции от управляющей части. При его использовании необходимы:

- закрытый безопасный корпус;
- предохранитель;
- защита от короткого замыкания;
- правильная разводка силовой части;
- adequate heat dissipation для SSR;
- проверка напряжения, тока и мощности конкретного реле.

Заявленная производителем нагрузка «до 8 А» не означает, что любой SSR безопасно коммутирует 8 А постоянно.

### Программная безопасность

- замените SSID, пароли Wi-Fi и MQTT;
- не используйте значения из `json_config.h` без изменений;
- не выставляйте web-интерфейс устройства в Интернет;
- ограничьте доступ к MQTT-брокеру;
- используйте отдельного пользователя MQTT с минимальными правами;
- не подключайте силовую нагрузку к GPIO без проверки схемы.
